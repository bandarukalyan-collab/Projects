# Functional Specification — Greeting Service

> Auto-generated by `/create-pod-knowledge`. Updated by `/update-knowledge`.

## 1. Overview

The Greeting Service provides personalized greeting messages through a REST API, a web interface, and a CLI tool.

## 2. Actors

| Actor | Description |
|-------|-----------|
| **End User** | Requests a greeting via the web frontend or CLI |
| **API Consumer** | Integrates directly with the Greeting API |
| **Administrator** | Manages greeting templates and locales |

## 3. Features

### F1 — Basic Greeting
- The API returns a greeting message when called with no parameters.
- Default greeting: `"Hello, World!"`

### F2 — Personalized Greeting
- The API accepts an optional `name` query parameter.
- When provided, the greeting includes the name: `"Hello, {name}!"`

### F3 — Locale Support *(planned)*
- The API accepts an optional `locale` parameter (e.g., `en-US`, `fr-FR`).
- Greeting templates are stored per locale.
- Unsupported locales return HTTP 400 with an error message.

## 4. Business Rules

| # | Rule | Details |
|---|------|---------|
| BR-1 | Name length | Name must be 1-100 characters |
| BR-2 | Default locale | If no locale specified, use `en-US` |
| BR-3 | Unsupported locale | Return 400 Bad Request with descriptive error |

## 5. Use Cases

### UC-1: Get Default Greeting
1. User calls `GET /api/greeting`
2. API returns `{"message": "Hello, World!"}`

### UC-2: Get Personalized Greeting
1. User calls `GET /api/greeting?name=Alice`
2. API returns `{"message": "Hello, Alice!"}`
